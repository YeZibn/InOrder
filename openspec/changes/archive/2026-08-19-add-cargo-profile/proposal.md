## Why

当前订单上下文只保留用户原始货物表达，无法为后续车型边界校验提供重量、体积、尺寸和运输属性。需要增加一个由 LLM 生成的货物约束画像，同时保留原始货物字段不被覆盖。

## What Changes

- 新增基于完整原始货物上下文生成货物画像的能力。
- 明确画像字段：数量、重量、尺寸、体积、可堆叠性、易碎性和温度要求。
- 为每个推断值记录来源、置信度、假设和警告。
- 汇总当前货物的总重量和预计装车占用总体积。
- 货物发生变化时重新生成并整体替换画像，避免派生数据重复累加。
- 本 change 不包含车型推荐、车型筛选、装箱坐标或 3D 装箱算法。

## Capabilities

### New Capabilities

- `cargo-profile`: 使用 LLM 将原始货物信息转换为可计算、可解释的货物约束画像。

### Modified Capabilities

- `conversation-order-context`: 在订单上下文中保存可序列化的货物画像及其汇总结果，同时继续保留原始货物列表。

## Impact

- 影响 `OrderContext` 的派生货物画像字段及其 JSON 输出。
- 新增 LLM 画像解析器、结构化输出校验和画像生成接口。
- 订单处理链路后续可调用画像生成，但本 change 不改变现有 extract 的原始实体契约。
- 需要补充画像模型、提示词、错误处理和测试；不引入车型选择依赖。

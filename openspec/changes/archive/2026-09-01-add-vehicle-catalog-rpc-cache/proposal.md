## Why

车型数据会因装货城市不同而变化，继续将完整车型表固化在 Python 进程中会造成数据更新滞后，也无法由主数据服务统一维护。需要引入独立车型目录服务，并在 Python 侧增加低延迟缓存和故障回退，避免车型服务短暂不可用影响下单流程。

## What Changes

- 抽象统一的车型目录 Provider，供车型匹配、归一化、Prompt 词汇和车型估算共同使用。
- 增加按城市查询车型及特殊规格的 RPC 客户端，支持全国默认数据和城市覆盖数据。
- 增加起点城市优先、用户定位城市兜底的有效城市选择逻辑。
- 增加进程内不可变快照缓存、城市级刷新锁、双重检查和 single-flight 刷新。
- 增加过期缓存、本地全国默认快照和 RPC 超时/失败回退策略。
- 在车型结果中记录有效城市、目录来源、版本及是否使用过期数据。

## Capabilities

### New Capabilities

- `vehicle-catalog-rpc`: 提供城市化车型目录 RPC、缓存、锁和故障回退能力。

### Modified Capabilities

- `vehicle-resolution-and-estimation`: 车型估算读取城市目录，并记录目录来源和有效城市。
- `vehicle-catalog`: 车型目录从单一本地表扩展为 Provider 统一访问和远程主数据覆盖。

## Impact

- 影响车型 catalog、归一化、上下文更新、车型估算及 API 请求模型。
- 新增 RPC/HTTP 传输配置、缓存和并发控制组件。
- 保留本地全国默认数据作为开发、测试及服务故障兜底，不改变现有基础车型字段。

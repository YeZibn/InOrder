## Context

当前 `OrderContextReducer` 对货物属性直接保存字符串，并尝试从字符串中提取数字进行累加。LangExtract 为未出现的可选属性返回 `null` 时，这种做法会导致错误；跨单位表达也无法安全计算。本 change 先建立原始货物放置层，后续归一化和估算在此基础上扩展。

## Goals / Non-Goals

**Goals:**

- 将货物属性统一存成原始值列表。
- 让 `add` 操作安全地追加多轮输入。
- 忽略 `None`、空字符串和缺失属性。
- 保持现有订单上下文 JSON 序列化能力。

**Non-Goals:**

- 不解析或换算重量、数量、体积单位。
- 不计算货物总重量、总体积或尺寸。
- 不使用 LLM 推断货物属性。
- 不实现车型推荐或装载计算。

## Decisions

1. **使用列表保存原始表达。** `weight`、`quantity`、`volume` 和 `dimensions` 均保存为列表；相比直接使用 `"a + b"`，列表保留了每次输入的边界，便于未来归一化。

2. **按货物名称聚合。** 同一 `name` 对应一条 cargo 记录；名称不同则创建不同记录。当前不做同义词归一或大小写语义判断。

3. **区分 action。** `set`/`replace` 将本条货物的属性列表替换为本次非空属性；`add` 将本次非空属性追加到现有列表；`remove` 删除整条货物记录。

4. **空值不持久化。** `None`、空字符串和空列表都视为未提供。列表中不保留空值，也不让空值触发任何计算。

5. **兼容迁移。** reducer 读取历史上下文中仍为字符串的货物字段时，将其视为单元素原始列表；新写入统一使用列表结构，避免一次性迁移已有会话数据。

## Risks / Trade-offs

- [Risk] 下游暂时无法直接得到重量总和 → Mitigation：明确这是原始放置阶段，后续增加独立货物归一化节点。
- [Risk] 同名货物可能实际是不同批次 → Mitigation：当前只按现有 `name` 合并，批次/货物标识留给后续需求。
- [Risk] 旧上下文格式混用 → Mitigation：读取时兼容标量，写入时统一列表，并增加序列化测试。

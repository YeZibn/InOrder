## Why

多轮订单中，同一种货物的新增数量会保存在原始货物记录的数组中，例如重量为 `["1吨", "1吨"]`。当前货物画像模型可能只读取其中一项，导致画像、汇总和车型估算低估实际运输规模。需要明确原始记录的累加语义，并保证画像始终从完整原始数据派生。

## What Changes

- 明确重量、数量、体积和尺寸数组表示同一货物的多次累加记录。
- 要求货物画像在生成单货物画像前先合并全部原始记录，并将可解析数值换算到统一单位后求和。
- 要求货物画像汇总与各货物画像的合计保持一致，避免重复使用旧画像。
- 保留 `cargo` 中的用户原始表达；`cargo_profiles` 和汇总继续作为可整体替换的派生数据。
- 增加画像聚合与一致性校验的测试覆盖。

## Impact

- 影响 `cargo_profile` Prompt、解析/校验逻辑及画像更新节点。
- 车型估算将使用正确的合计重量、体积和整体尺寸。
- 不改变对外 API 字段结构，不泄露或覆盖用户原始货物表达。

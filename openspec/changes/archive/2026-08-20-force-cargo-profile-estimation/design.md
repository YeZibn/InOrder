## Context

当前简化画像已经具备直接数值字段，但 prompt 仍允许模型在“一吨苹果”这类可利用货物常识估算的场景返回空体积。此 change 只收紧估算策略，不改变画像字段结构。

## Goals / Non-Goals

**Goals:**

- 强制模型将货物类型与运输规模信息转化为可用的体积和尺寸估算。
- 让 `reason` 体现从总重量或数量到装车空间的推理链。
- 保留仅有货物名称时返回 `null` 的边界。

**Non-Goals:**

- 不建立本地货物知识库或确定性物性计算器。
- 不执行车型推荐、车型筛选或装箱算法。
- 不增加新的画像字段。

## Decisions

### 1. 采用物流常识推理，而非本地固定公式

Prompt 要求 LLM 根据常见单件重量、箱规、包装、堆积密度和装载方式完成多步估算。这样可以覆盖苹果、香蕉等不同货物，避免将单一固定密度硬编码到本地。

### 2. 以“运输规模信息”作为 null 边界

货物类型 + 重量、数量、包装、体积或尺寸中的任意一项，即视为具有规模信息，必须尽力估算。只有货物类型本身没有任何规模信息时，才允许核心数值为 null。

### 3. 整体尺寸优先表达装车占用

模型输出的 `dimensions_cm` 解释为预计装车占用的整体长宽高，便于未来与货厢边界比较，而不是输出苹果单果尺寸或纸箱单箱尺寸。

## Risks / Trade-offs

- [常识估算可能偏差较大] → 通过 `reason` 暴露假设；后续车型校验可将其视为初筛约束。
- [不同 LLM 对同一货物估算不一致] → 保持 prompt 推理链和典型测试场景稳定，后续再增加评测集或范围值。
- [过度推理导致模型编造] → 明确“仅货物名称”仍可返回 null，且要求 reason 说明运输规模缺失。

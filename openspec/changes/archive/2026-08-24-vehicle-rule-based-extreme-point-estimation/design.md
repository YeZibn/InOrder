## Context

当前车型解析节点在用户车型无法匹配时调用 `VehicleResolutionResolver` 的 LLM，让模型从车型目录中选择一个 code。车型目录已经包含固定的能力范围，货物画像也提供每种货物的整体尺寸，因此车型估算可以改为纯计算，并扩展为多货物整体箱的简化极点装载。

## Goals / Non-Goals

**Goals:**

- 移除 LLM 车型选择，保证结果确定、可重复和可测试。
- 用车型表最大能力值进行快速过滤。
- 实现每种货物一个整体箱、六种旋转和基本极点不重叠判断。
- 返回 0 至 3 个真实通过计算的候选车型，并给出排序原因。
- 用户车型匹配成功时保留单一用户结果并短路估算。

**Non-Goals:**

- 不拆分货物画像为单件或箱数。
- 不实现完整三维装箱优化、复杂堆叠、承重分布、装卸顺序或多车拆单。
- 不调用 LLM 选择车型，不执行用户指定车型能力校验或自动纠正。

## Decisions

1. **使用车型能力范围上限。** 计算使用 `length_m[1]`、`width_m[1]`、`height_m[1]`、`volume_m3[1]` 和 `payload_t[1]` 作为车型估算边界；这是当前估算表的明确上限。
2. **先总量过滤，再极点装载。** 总重量和总体积快速排除明显不适配车型，逐货物极点计算负责处理形状、旋转、边界和重叠。
3. **每条画像是一个整体箱。** 不按 quantity 展开，不将多种货物合并为一个外包络；按体积和最大边排序放置较大货物优先。
4. **候选排序与数量。** 通过车型按最大体积、载重余量和装载余量排序，最多返回三个；不够三个不补充失败车型。
5. **结果模型扩展。** 保留 `user_matched` 单车型结果；`estimated` 结果增加候选列表，最终写入上下文的主车型取排序第一候选，候选列表保留在图结果中。

## Risks / Trade-offs

- [整体箱尺寸是包络估算，不是单件装箱数据] → 明确这是第一版简化极点计算，后续再增加单件/包装数据。
- [范围上限可能高估真实车辆空间] → 在结果原因中注明使用车型表上限，未来可替换为精确车厢内部尺寸。
- [贪心极点顺序不保证全局最优] → 大货物优先、六方向尝试，并保留最多三个候选供用户选择。

## Migration Plan

1. 增加多候选结果模型和确定性车型计算器。
2. 替换车型估算 resolver 的 LLM 调用，保留用户车型匹配短路。
3. 更新订单图状态和 CLI 展示候选车型。
4. 增加多货物、旋转、重叠、边界和最多三个候选测试，运行完整测试。
